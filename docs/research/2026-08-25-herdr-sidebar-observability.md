# Herdr Sidebar Observability Research

Date: 2026-08-25
Scope: primary sources in this repository only. Research note; no implementation or commit.

## Executive constraints

- Information belongs where the user makes the decision, but every added dimension must earn more value than its visual and rendering cost. One visual channel must carry one semantic; containers must remain stable; the largest known dataset is 471 turns / 32 lanes; selection must follow attention. These are the governing UI constraints for a sidebar redesign. (`docs/design-principles.md:32-40`, `docs/design-principles.md:42-79`, `docs/design-principles.md:83-98`)
- The current product contract is deliberately compact: a badge is a context bar plus either a cost/age fact or one alert, plus ready/not-linked/freshness state. It is not a full model or cost card. (`docs/herdr-support.md:42-54`)
- Pane/session attribution must stay evidence-based. Native session identity is preferred; cwd fallback may be ambiguous; the plugin must not borrow another pane's telemetry just to render a green state. (`docs/herdr-support.md:62-72`, `docs/herdr-support.md:189-202`)
- Sidebar installation is optional, consent-based, reversible, and must preserve user-owned rows. A plugin-created table may be removed whole; a user-owned or extended table keeps non-ccxray rows. (`plugins/herdr/README.md:22-28`, `docs/herdr-support.md:48-50`, `docs/herdr-support.md:189-202`)

## Existing sidebar shape and hard layout rules

- Fresh install creates `[ui.sidebar.agents]` with `row_gap = 0`, native row 1 `state_icon · agent · state_text`, four mutually exclusive context-colour rows, and a two-row row-3 pair (`$facts`, `$alert`). The config therefore has seven row entries but only three visible lines because Herdr skips rows whose tokens are all empty. (`plugins/herdr/bin/install-sidebar-summary.js:8-29`, `plugins/herdr/bin/install-sidebar-summary.js:52-68`, `test/herdr-plugin.test.js:1344-1367`)
- Row ownership is fixed: row 1 owns Herdr process state / not-linked state; row 2 owns context percentage, sparkline, and colour; row 3 owns one non-context, non-process concern or the cost/age fact. Repeating `full`, `near full`, `blocked`, or `not linked` in row 3 is explicitly rejected as duplication. (`plugins/herdr/bin/refresh-badges.js:93-125`, `plugins/herdr/bin/lib/ccxray.js:403-515`, `test/herdr-plugin.test.js:1079-1111`, `test/herdr-plugin.test.js:1205-1223`)
- Colour semantics are exclusive: unknown gray, `ctx <= 40%` green, `40% < ctx <= 80%` yellow, `ctx > 80%` red. Stale data withdraws the confident colour while retaining the percentage and reason text. (`plugins/herdr/bin/lib/ccxray.js:337-342`, `plugins/herdr/bin/lib/ccxray.js:982-1023`, `docs/herdr-support.md:149-151`)
- Width is measured in this order: `CCXRAY_HERDR_SIDEBAR_COLS`, Herdr plugin context fields, `herdr pane layout`; valid values are clamped to 8–96 columns, with 18 as fallback. Context signals are omitted when the sidebar is narrow; row-3 text is clipped locally with an ellipsis rather than left to Herdr. (`plugins/herdr/bin/lib/ccxray.js:1833-1860`, `plugins/herdr/bin/lib/ccxray.js:516-530`, `plugins/herdr/bin/refresh-badges.js:83-91`, `plugins/herdr/bin/refresh-badges.js:118-124`, `test/herdr-plugin.test.js:1236-1250`)
- Installer migration is conservative: it deletes only complete superseded token sets inside the rows array, preserves user-extended rows, is idempotent, and validates/reloads atomically with a backup and restore-on-config-error path. (`plugins/herdr/bin/install-sidebar-summary.js:115-179`, `plugins/herdr/bin/install-sidebar-summary.js:228-317`, `plugins/herdr/bin/remove-sidebar-summary.js:13-60`, `test/herdr-plugin.test.js:1346-1482`)

## Token, metadata, and evidence limits

- Herdr pane metadata has a hard cap of 16 unique token names across set + clear. The plugin internally computes more, but the current pane report deliberately sends only `xray`, the four `ctx_bar_*` variants, `facts`, and `alert`—seven names. Internal `summary`, `ctx_band`, and `ctx_bar` are cleared as cleanup; old atomic tokens are not cleared because an unmigrated user config may still render them. (`plugins/herdr/bin/refresh-badges.js:273-301`)
- A token that is not referenced by the user's sidebar config does not render. This is why stale state is copied into `$ctx` as `32% stale` in addition to the summary/alert paths, and why a redesign must either preserve the managed rows or explicitly support legacy configs. (`plugins/herdr/bin/refresh-badges.js:160-180`, `test/herdr-plugin.test.js:1963-1997`)
- Metadata writes are not free: Herdr republishes pane metadata and a full-screen agent TUI repaints. Identical payloads are skipped; a TTL still forces a rewrite after half the TTL so Herdr does not drop the badge. The comparison must include tokens, clears, state labels, agent, title, and display agent. (`plugins/herdr/bin/lib/ccxray.js:2128-2184`, `test/herdr-plugin.test.js:695-726`, `test/herdr-plugin.test.js:794-880`, `test/herdr-plugin.test.js:4960-4988`, `test/herdr-plugin.test.js:5165-5201`)
- The normal badge TTL is 600,000 ms. Working refreshes use a bounded loop: 20 s default interval, refresh on index mtime change, final refresh at idle, pane-gone/max-age exits, four-hour default max age, and one PID file per pane. (`plugins/herdr/bin/refresh-badges.js:253-309`, `plugins/herdr/bin/badge-refresh-loop.js:17-54`, `plugins/herdr/bin/badge-refresh-loop.js:104-155`, `test/herdr-plugin.test.js:2100-2140`)
- Cost and turn totals must come from the hub's per-session aggregate when available, with only post-flush turns topped up. The raw index reader is a maximum 4 MiB tail, so tail-derived tool counts and historical totals are lower-bound/sample evidence; response IDs are deduplicated before summing. (`plugins/herdr/bin/lib/ccxray.js:209-273`, `plugins/herdr/bin/lib/ccxray.js:919-963`, `plugins/herdr/bin/lib/ccxray.js:1059-1068`, `docs/herdr-support.md:189-202`, `test/herdr-plugin.test.js:882-981`)
- Aggregate cost must use the shared confidence fold. With `public/format.js`, fallback share controls `~` and precision; without it, degraded mode is intentionally unmarked and retains only `—` or `+`, never a worst-of `~`. (`plugins/herdr/bin/lib/ccxray.js:650-719`, `docs/herdr-support.md:100-108`, `test/herdr-plugin.test.js:984-1057`)
- Context provenance is limited in the badge: 200K is a default assumption, observed 1M evidence is distinct, and overflow is contradicted. The badge can mark `?` / `✗` and neutralize colour, but does not carry the dashboard denominator citation. Provider-native cache/tool evidence also differs, and Codex/Grok tool counts may be lower bounds. (`plugins/herdr/bin/lib/ccxray.js:610-629`, `plugins/herdr/bin/lib/ccxray.js:963-977`, `test/herdr-plugin.test.js:2037-2097`, `docs/herdr-support.md:92-108`, `docs/herdr-support.md:110-120`)

## Keyboard and row interaction behavior

- Quick Start is a cursor menu: Up/Down or `j`/`k` moves, Enter activates, `q`/Esc/Ctrl+C closes; disabled items remain visible but are skipped by cursor movement, while number/letter hotkeys remain discoverable. (`plugins/herdr/README.md:22-28`, `test/herdr-plugin.test.js:253-308`)
- Herdr manifests cannot declare keybindings; they are user config. The plugin's optional bindings are `prefix+m` for Mission Control and `prefix+shift+m` for Quick Start, with collision detection, backup, config validation, reload, and reversible removal. (`plugins/herdr/README.md:42-68`, `plugins/herdr/herdr-plugin.toml:59-77`, `test/herdr-plugin.test.js:4540-4665`)
- Mission Control uses Up/Down or `j`/`k`, Enter to focus the exact pane, `d` for dashboard deep-link, `f` for filters, `r` refresh, `?` help, and `q`/Esc close. Selection follows pane identity across reorder and falls back to the nearest surviving row; `CCXRAY_MISSION_MAX_ROWS` and `CCXRAY_MISSION_COLS` constrain the view. (`plugins/herdr/README.md:149-155`, `plugins/herdr/bin/mission-control.js:206-227`, `plugins/herdr/bin/mission-control.js:240-333`)
- For located panes, row 1 must hand the native Herdr state text back by sending `--clear-state-labels`; only `not linked` / `no hub` states receive ccxray state labels. (`plugins/herdr/bin/refresh-badges.js:253-309`, `test/herdr-plugin.test.js:1253-1295`)

## Refresh and acceptance signals

- Manifest hooks are startup fan-out plus `pane.agent_detected` and `pane.agent_status_changed`; the tests require all three. The fan-out runs status, usage, and agent-list discovery once, shares only successful reports, caps each child at 10 s by default, and reports `timed out` separately from `failed`. (`plugins/herdr/herdr-plugin.toml:8-27`, `plugins/herdr/bin/refresh-all-badges.js:15-99`, `test/herdr-plugin.test.js:221-228`, `test/herdr-plugin.test.js:4724-4861`)
- A stale marker is evidence-driven: only a completed transcript turn newer than ccxray's newest index evidence qualifies; metadata-only writes, zero-token assistant records, finished sessions, missing transcripts, and normal sub-threshold lead do not. Default threshold is 10 minutes; the rescan is detached and can be disabled without removing the marker. (`plugins/herdr/bin/lib/ccxray.js:745-755`, `plugins/herdr/bin/lib/ccxray.js:866-917`, `plugins/herdr/README.md:124-138`, `test/herdr-plugin.test.js:1819-1961`)
- The strongest existing acceptance signals are: seven config rows but three visible lines; migration removes superseded rows and is idempotent; row 3 has exactly one of `$facts`/`$alert`; narrow alerts fit; native row 1 state is preserved; identical writes are skipped but TTL refreshes; badge/Mission Control model and ctx% agree; aggregate cost and response-ID dedup agree; provenance markers are correct; refresh fan-out shares work and labels timeouts; working loops refresh on interval/index change and terminate at lifecycle boundaries. (`test/herdr-plugin.test.js:1161-1251`, `test/herdr-plugin.test.js:1253-1296`, `test/herdr-plugin.test.js:1302-1482`, `test/herdr-plugin.test.js:1642-1732`, `test/herdr-plugin.test.js:2037-2140`, `test/herdr-plugin.test.js:4724-4861`)

## Design takeaway

The safe redesign envelope is a compact, width-aware three-line sidebar: preserve native Herdr state, give context one row and one colour meaning, give the third row one fact or one ranked non-owned alert, and spend no new token names unless the 16-name metadata budget and row ownership are re-established. Any stronger observability claim must carry its evidence state (`not linked`, `?`, `✗`, stale, lower-bound/estimated) and must not infer cross-pane identity or task outcome. (`docs/design-principles.md:42-67`, `plugins/herdr/bin/refresh-badges.js:258-301`, `docs/herdr-support.md:189-202`)
